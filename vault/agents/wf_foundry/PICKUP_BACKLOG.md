Pick an outstanding issue on galaxyproject/foundry with work/ready-implement or work/ready-research. Skip issues labeled upstream/* or requires-iwc-inputs. Prioritize priority/mvp issues over priority/v2 issues. Prioritize roadmap/main over roadmap/substep over roadmap/off.

When you pick an issue, claim it on GitHub: swap its work/ready-* label for work/in-progress and comment that an agent picked it up. Record it in index.md with a status of WIP - a line - <issue link> | AGENT WIP. If you give up, restore the work/ready-* label.

- If the issue had work/ready-research - please have a subagent research the problem and prepare a concise, readable comment for the issue. Have another subagent review that comment for correctness and clarity, fix any issues the subagent raises that seem important. The comment should remain concise and readable. Use <details> to help readability when needed. Post the comment and swap work/in-progress for work/needs-review. After the comment is posted, update the status line for this issue in index.md to <issue link> | AGENT POSTED COMMENT FOR REVIEW
- If the issue had work/ready-implement - please have a subagent research the problem and write a detailed plan to ./plans/<issue_number>_PLAN.md. Have a subagent review the plan for correctness and clarity and fix the plan. Then implement the plan. Have a subagent review it for correctness and clarity. Open a DRAFT PR for this work and update the status line in index.md to <issue link> | <pr link> | short_description. If the issue cannot be completed without significant clarification or very important human design decisions - please stop and write ./plans/<issue_number>_DESIGN_QUESTIONS.md, post the questions as an issue comment, swap work/in-progress for work/needs-review, and update the status line in index.md as <issue link> | REQUIRES DESIGN SESSION.
