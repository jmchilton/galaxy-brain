# Workflow Brief: nf-core/cutandrun 3.2.2 (whole pipeline)

## Workflow

### Objective

John: "Convert the whole pipeline to an equivalent Galaxy workflow." (from `caller-request.md`; these are the only words from John).

The source describes itself as an `Analysis pipeline for CUT&RUN and CUT&TAG experiments that includes sequencing QC, spike-in normalisation, IgG control normalisation, peak calling and downstream peak analysis.` (nextflow.config:338). It takes paired-end CUT&RUN or CUT&TAG FASTQ libraries described by a sample sheet that groups libraries into experimental groups and replicates and names an IgG control group for each target group, plus a target genome FASTA, a gene annotation and, in the default mode, a spike-in genome FASTA. Per library it produces filtered alignments, normalised coverage tracks (bedGraph and bigWig) and, for target libraries, peaks called against the paired IgG control or against a threshold. Per group (or across all samples) it produces consensus peaks. Peak QC (FRiP, peak counts, reproducibility), fragment-length histograms, deepTools heatmaps and QC, a genome-browser session and an aggregate QC report summarise the run.

### Decisions

Only the first item is an expert decision. The others are recorded with their source so the expert can confirm or override them.

- John: "Convert the whole pipeline to an equivalent Galaxy workflow." No other Galaxy requirement (coordinator, `caller-request.md`).
- Coordinator context (not John's words): IgG controls, spike-in normalisation, the alternative peak caller and the alternative normalisation modes stay in scope; how they are supplied or selected is for the brief.
- Agent decision, proven in build v0: IgG controls follow the source's sample-sheet contract (five columns; a row's `control` names a control group; that group's rows are controls) and its replicate assignment (replicate to replicate when counts match, otherwise control replicate 1). Controls are never peak-called, a control replicate may serve several targets, and the source's `use_control` choice is offered, on by default; with it off, named controls are processed but unused for peaks, and the run notes the source's warning. Evidence: build v0 `run-summary.md` and `workflow-test-result.json`: `test` paired `h3k27me3` R1 with `igg_ctrl` R1; `test_full_small` paired replicate to replicate, each IgG replicate serving two targets; `test_no_control` and the None-mode case with controls off called against the SEACR threshold. The control-replicate-1 fallback was not reached by any test. Was an open question (high) at v0.
- Agent decision, proven in build v0: Spikein is the default mode, as in the source. In that mode the spike-in genome FASTA is required and a run without it stops; the factor is `normalisation_c` (10000) over the library's concordant spike-in pairs aligned once or more than once, factor 1 when that count is 0, applied to targets and IgG alike. In other modes no spike-in input is needed and no spike-in alignment runs. Evidence: build v0 `run-summary.md`: factors 10000 and 28.41 on `test`, the zero fallback (factor 1) for `h3k27me3` R2 on `test_full_small`, the CPM and None cases ran without a spike-in FASTA, and the Spikein case without one failed at the intended step.
