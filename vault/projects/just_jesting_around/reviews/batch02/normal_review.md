## Test challenge and scope

These tests belong at the client layer under Galaxy's writing-tests decision tree. They check rendered card output/actions, client request construction, cache recovery, polling timing/lifecycle, and filter parsing/serialization without requiring a Galaxy server. Moving these contracts to backend API or browser tests would obscure client behavior and make precise polling/error combinations harder to exercise. This iteration introduces no product behavior that warrants a new Selenium/Playwright scenario.

No new test merely mirrors the page factory implementation. Its two existing consumer suites exercise the returned shapes; adding property-by-property factory tests would duplicate fixtures without protecting a meaningful additional contract. Existing narrow directive-routing checks were retained alongside rendered markdown assertions; they are not claimed as end-to-end sanitization coverage.

MSW remains appropriate for the pages API's real request construction. The small tool-store axios rejection/recovery sequence remains readable and bounded; replacing it with handler counters/replacement would not improve this three-case suite. The shared `wait`, `nth`, `withPlugins`, and existing notification factories are reused where they fit. The local watcher lifecycle helper and component-specific mount helper do not justify a general shared harness with unrelated sibling tests.

The page factory extraction is supported by two identical consumers. Revision fixtures have one immediate consumer, so further extraction is deferred. Notification factory determinism/malformed seen timestamps and a typed Tool factory for concrete sibling consumers are worthwhile follow-ups, not reasons to widen this iteration. No production, E2E, or README changes are needed, and no generic guidance addition is justified by these edits.
