# Iteration 06 test challenges

No test-layer changes or additional E2E tests are warranted for this readability-only iteration. Challenged each affected suite against `doc/source/dev/writing_tests.md` and the shared test-challenge instructions, while preserving the user's existing test coverage.

- Application construction has lightweight public contract checks: bootstrapped defaults, localization binding, user identity, and replacement-instance behavior. The original setup export has no consumers. A browser test would add server setup without improving these constructor checks.
- Dataset storage uses real component lifecycle/API behavior with MSW responses and shallow child boundaries. Its initial loading checkpoint, failure rendering, and response forwarding exercise behavior independently of child markup. Existing browser storage coverage in `lib/galaxy_test/selenium/test_history_storage.py` exercises storage navigation and deletion; it does not replace the deterministic loading/failure cases here.
- Selected-item tests exercise a real composable, real Vue watchers, real history filters, and a real Pinia store. Query-versus-loaded counts and selection-break transitions are meaningful public behavior rather than mirrors of implementation statements. The query-break callback is an appropriate observation boundary. The refactor removes the accidental dependence on preceding query cases and disposes the composable's watchers/listeners after each case.
- Object-store tests cover public initial state, asynchronous actions, and lookup behavior with real Pinia. The two initial-state checks are small but preserve the agreed baseline; there is no added trivial suite. A typed shared domain factory replaces duplicated object construction across store and component consumers.
- TUS tests retain an external transport fake rather than faking the Galaxy wrapper. `FakeUpload` implements the library's interface and keeps the actual wrapper fingerprint, retry timer, callbacks, promise settlement, resume ordering, and abort checks under test. A backend API test can validate server uploads but cannot directly observe browser reader extraction or the wrapper's exact timer boundary. Existing upload browser tests and upload-configuration integration tests cover other layers; no new product behavior in this iteration calls for another browser scenario.
- The supporting object-store dropdown still uses its existing real event/API behavior and scoped mocks. Only its fixture moved to the shared factory; its success/error assertions and existing case count are unchanged. It remains eligible for a separate full readability iteration.

The final result supplied by the coordinator has 38 passing cases across six affected files, with all selected cases retained. No assertions were removed to satisfy this challenge, and no production or E2E code changed. The existing README already explains the useful abstractions and async boundaries; this review proposes no new general advice.
