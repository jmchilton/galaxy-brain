## Finding and disposition

The initial upload refactor omitted `src: "url"` from the second element in the legacy multiple-URL case. That was a real loss of an existing assertion, despite the retained URL and array length checks. The coordinator restored it; independently verified the final matcher includes both original values.

Shuffled validation then exposed interference between three supporting history retry scenarios. Production `retryCounts` is module-scoped and keyed by history ID, so replacing Pinia alone does not isolate repeated failing requests for the same ID. Independently inspected the focused correction: the retry recovery, retry exhaustion, and awaited error scenarios now use distinct IDs consistently in getters and the recovery response. The recovery request still returns the same ID it requests, and the exhaustion case still requires exactly `MAX_RETRIES + 1` calls. No production retry behavior or expected result changed.

No blocking issue remains. The iteration adds no production behavior, dependency, or configuration change. The shared helpers have two concrete consumers each, and supporting edits remain focused on helper use and the shuffled-run retry isolation repair. Existing `setupTestPinia`, notification fixtures, and timing helpers are reused. Broader graph scheduling-schema alignment or store disposal APIs would be production changes outside this readability iteration; the test's explicit boundary and scoped cleanup are sufficient here. No new README guidance or marginal advice is warranted.
