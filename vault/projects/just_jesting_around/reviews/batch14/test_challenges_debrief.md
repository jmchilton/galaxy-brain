The change improves testing boundaries: Markdown config and visualization queries now use child props rather than component internals; InvocationsProvider awaits its actual promise and checks response data; form and headless cases keep real children where required. MSW remains the appropriate HTTP boundary, and existing page/object-store factories replace duplicate models. The graph's local reactive dependency doubles allow controlled ownership and SSE transitions without a running server; no reusable no-op implementation offers a clearer fit here.

The old graph test manufactured a new Vue computed and checked that it existed, which only tested Vue. Replacing that diagnostic with returned dependency identity and actual graph output preserves the component contract and removes meaningless scaffolding. Other negative assertions and all original variations remain intact.

The Markdown invocation-ID mismatch is pre-existing: the component passes a string to an action expecting `{ id }`, and the permissive handler proves mapping without validating request identity. A production fix should include explicit request-ID evidence. No new feature or production behavior is introduced in this iteration, so extending browser infrastructure or adding slow duplicate scenarios would exceed this readability batch. No E2E tests were added or run, and existing browser coverage is not represented as current execution evidence.

No test removal, higher-layer rewrite or extra shared helper is needed for this iteration. No additional best-practice text is justified.
