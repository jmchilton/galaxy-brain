# WorkflowInvocationState

Selected originator: `client/src/components/WorkflowInvocationState/WorkflowInvocationState.test.ts`. Baseline and final: **10 tests**.

The scenario inputs used to sit in two module-level lookup tables keyed by magic IDs. Each test named only an ID, so a reader had to cross-reference both tables to see what state was under test. Now each test seeds its own invocation and jobs summary through `storeInvocation(id, jobsSummary, overrides)`. That helper puts a copy of `invocation.json` in the mocked store. The scheduled, empty-states `terminalJobsSummary` is the base, and each test spreads in its running, error or `populated_state: "new"` variation inline. The mocked store getters read from those per-test maps. A top-level `beforeEach` clears the maps and resets both fetch spies. Before, the spies were only cleared in the first describe, and the error behaviour lived in a shared `mockImplementation` that branched on `"error-invocation"`. The error test now sets its throwing implementation itself.

The "hacky" `isInvocationAndJobTerminal` helper grepped the overview stub's HTML for `invocationandjobterminal="true"`. It is replaced by `findComponent(WorkflowInvocationOverview).props("invocationAndJobTerminal")`. The old helper also returned false when the overview was absent. So the not-found and error cases now assert `exists()` is false, and the other false cases assert the prop is `false`, which is stronger. Each test name now states the polling behaviour that the old inline comments explained. For example, "polls a new invocation once after the initial fetch" explains why the fetch count is 2. The tab describes are renamed for the state they check. The unused `fullPageHeading` and `spanElement` selectors and the stale `@param shallow` docblock are gone. The two `(originalModule as any)` casts became typed `vi.importActual<typeof Module>`, following `UserBeaconSettings.test.ts`, because the file did not pass `eslint --max-warnings 0` before this change.

Preserved: all 10 scenarios, with the same IDs and the same invocation and summary data. That includes `state: "new"`, `{ running: 1 }`, `populated_state: "new"`, `{ running: 1, error: 1 }`, `{ ok: 1, error: 1 }`, null store entries for the not-found case, and the thrown "User does not own specified item." message. Also preserved are every terminal/non-terminal check, every fetch count (1/0, 2/0, 1/1, 1/1, 1/0, 1/0), both alert variants and texts, the Report and Export `disabled` attributes, and Debug tab presence. Added: `toHaveBeenCalledWith({ id })` for the invocation fetch and the jobs-summary fetch. Changing the terminal-error summary to `{ running: 1, error: 1 }` fails the Debug-tab case on its terminal-state assertion.

Reuse: the existing `invocation.json` fixture, `getLocalVue`, and the typed `importActual` pattern. `tests/test-data` has no jobs-summary factory. Other invocation-store tests (`invocationStore.test.ts`, `MarkdownGalaxy.test.js`, `CommandPalette/providers/invocations.test.ts`) mock the store differently or use the real one, so the seeding helper stays local.

Validation: 10 tests pass shuffled (seed 260101). ESLint (`--max-warnings 0`), Prettier and full `vue-tsc --noEmit` are clean.

Guidance: none.
