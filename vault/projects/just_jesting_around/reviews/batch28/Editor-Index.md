# Workflow Editor Index

Selected originator: `client/src/components/Workflow/Editor/Index.test.ts` (follow-through from batch 27). Baseline and final: **30 tests**.

The three `(X as unknown as { name?: string }).name = "X"` writes to the shared production `ActivityBar`, `WorkflowGraph` and `ChangesIndicator` objects are gone, along with the stale comment that claimed they were required (and an orphaned `// Selectors` line). The `ActivityBar` and `ChangesIndicator` imports existed only for those writes, so they go too. The three mount paths (the default-mount `beforeEach`, `mountWithSteps`, `mountForNav`) now share one `mountEditor(props)`. It mounts on a fresh testing Pinia with datatypes seeded, uses `props` plus `withPlugins(localVue, pinia)` with stubs merged over `localVue.stubs` (the paths used to mix `global:` and `localVue:`), and drops the `Index as object` cast. It returns `{ wrapper, stateStore, stepStore }`, scoped to the id `WorkflowAttributes` receives. That keeps `mountForNav`'s temp-workflow id resolution. `mountLoadedEditor` adds the initial-load flush. Each case now mounts its own editor instead of reading describe-level `let wrapper/stateStore/stepStore`. The default-mount group calls `mountDefaultEditor()`, which keeps that group's `["moo", "cow"]` tags. `EDITOR_STUBS` is a constant. Its `WorkflowGraph` stub now always renders its slot (`<div><slot /></div>`); before, only the two node-inspector cases overrode it to do so. That is a deliberate unification: elsewhere no step is active, so the slot's `NodeInspector` doesn't render. Other changes:

- The four attribute change-tracking cases become one `it.each`. "tracks changes to annotations" is renamed "tracks changes to annotation" to match the other three.
- A local `toolStep()` builds the clone source and the inspector steps with the same field values as before.
- `clickActivity(wrapper, id)` replaces the inline activity-bar emits and `triggerOnNavigateToList`.
- `proceedFromSaveChangesModal(wrapper, "save" | "dontSave")` holds the positional `on-proceed` flags once.
- `SELECTORS` holds the save button, save-as modal and error modal selectors.
- An `afterEach` restores real timers, replacing the try/finally blocks.
- `enableAutoUnmount(afterEach)` is added.

Isolation fix: nothing reset mocks or restored spies between tests. The `createWorkflow` spy and `saveWorkflow` call history leaked across cases. Red check: deleting the name emit from "save-as field values are intact…" still passed on the original file, because the previous case's call satisfied `toHaveBeenCalledWith`. On the new file the same mutation fails. The top-level `beforeEach` now starts with `vi.resetAllMocks()`, which replaces the three `mockClear`s, both in-test `mockGetModule.mockReset()`s and onNavigate's `mockSaveWorkflow.mockReset()`. An `afterEach` adds `vi.restoreAllMocks()`, which also restores the console and `requestAnimationFrame` spies. The resets now run before mount instead of after it. That is equivalent: mount never calls `getModule`, which the retained `toHaveBeenCalledTimes(1)` shows. The temp-workflow case's post-mount `mockSaveWorkflow.mockClear()` is dropped because that case never asserts on `saveWorkflow`.

All 30 scenarios and every assertion are kept, with the same expected values (including the redundant `not.toBeNull`/`not.toBeUndefined` beside `toEqual`). One assertion is added: "prevents navigation only if hasChanges" now checks that no `update:confirmation` was emitted before the change. Red check: setting `hasChanges` before that line fails it. Async boundary: the old `beforeEach` mount gave each case a runner-supplied microtask gap before its body. "resolves datatypes" depended on it, because `WorkflowGraph` is `v-if`-gated on the async datatypes mapper, so it now flushes explicitly. The other cases that don't flush (four attribute trackers, readme close, three save-as cases, prevents-navigation) now start with the load slightly less advanced than before. They assert on `WorkflowAttributes`/modal children that render immediately, and they pass.

Stub red checks: renaming the `ChangesIndicator` key fails 3 tests, renaming `WorkflowGraph` fails 2, and renaming all three fails 30. A `<script setup>` child is matched in `stubs` by its file-derived name without any `.name` write. No `as unknown as { name` assignment remains in `client/src` tests.

Reuse: `withPlugins`, `emittedArg`, `mockUnprivilegedToolsRequest`, `testDatatypesMapper`. `createTestStep` (`Workflow/Editor/test_fixtures.ts`) was considered for the steps. It would change the test data (a default output, id-based position, no `content_id`/`tool_id`), so a local `toolStep` is used instead. No new shared helper.

Validation: 30 tests pass shuffled (seed `280101`, `NODE_OPTIONS=--no-webstorage`). Scoped ESLint and Prettier pass; full `vue-tsc --noEmit` passes.

Guidance: the README's "Stub with methods" example now models stubbing `<script setup>` children by name with no `.name` assignment. A one-line README note is warranted: a `<script setup>` child is matched in `stubs` by its file-derived name.
