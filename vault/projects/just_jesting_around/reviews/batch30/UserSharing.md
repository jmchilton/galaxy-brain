# UserSharing

Selected originator: `client/src/components/Sharing/UserSharing.test.ts`. Baseline and final: **6 tests**.

`mountUserSharing(item)` replaces `mountComponent`: it seeds the current user on its own Pinia before mounting (it used to be set after `mount`, then flushed), installs the Pinia with `withPlugins`, mounts with `props`, and drops the `UserSharing as object` cast and legacy `localVue`/`pinia`/`propsData` options. The three repeated permission-change items and the two "shared with existing@test.com" items become `makeItemRequiringPermissionChanges()` and `makeItemSharedWithExistingUser()` on top of the existing local `makeItem`, with the same data. Cases are grouped under "permissions modal" and "sharing with users", selectors are constants, and auto-unmount is added. The unused `axios` automock (emails are not exposed and the user is not an admin, so no search request runs) and the `vi.clearAllMocks()` that nothing relied on are gone, as is the unneeded localization instrumentation.

Assertion changes. The four `emitted(...)).toBeTruthy()` plus `?.[0]` checks become exact `toEqual`s over all emissions, so each event now has to fire exactly once. That exposed a test artifact: the modal tests called `GModal.vm.$emit("ok" | "cancel")` directly, which skips the native `<dialog>`. On cancel the parent then closed the still-open dialog, whose `close` event made GModal emit a second `cancel`, so `cancel` reached the parent twice. A real click on the modal's Cancel button closes the dialog first and emits once. The modal cases now click GModal's Ok/Cancel footer buttons through `clickModalButton(wrapper, text)`, which throws if the button is missing. The confirm case also checks the modal closes. The Cancel-button reset case now checks the visible email tags before (`existing`, `new`) and after (`existing`) the click, alongside the original disabled-Save check, so the reset itself is asserted.

Preserved: modal closed without permission changes; open with "A Dataset" listed; share emitted with `[]` and `make_accessible_to_shared` on confirm; modal closed and cancel emitted on cancel; share emitted with both emails on Save; cancel emitted and Save disabled after Cancel.

Reuse: `getFakeRegisteredUser`, `getLocalVue`/`withPlugins`; no shared factory exists for `ShareableHistoryWithStatus` (`WorkflowInvocationShare.test.ts` builds a different, non-status shape), so `makeItem` stays local. `clickModalButton` stays local too: about 30 `GModal` `vm.$emit("ok" | "cancel")` calls elsewhere (WorkflowMissingToolsRequest, RenameModal, UserDeletion, WorkflowInvocationShare, ...) could share it. Whether each is affected by the double `cancel` was not checked, so moving them over is a follow-up, not part of this change.

Validation, from `client/`: 6 tests pass shuffled (seed `300101`, `NODE_OPTIONS=--no-webstorage`). ESLint (`--max-warnings 0`), Prettier and `vue-tsc --noEmit` pass.

Guidance: when a test needs a GModal outcome, click its footer buttons rather than `vm.$emit`-ing `ok`/`cancel`. The synthetic emit leaves the native dialog open, so closing it later fires a second `cancel`; exact emission assertions catch this and `toBeTruthy()` hides it.
