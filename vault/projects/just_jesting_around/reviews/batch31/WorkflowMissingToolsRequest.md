# WorkflowMissingToolsRequest

Selected originator: `client/src/components/Workflow/Run/WorkflowMissingToolsRequest.test.ts`. Baseline **16 tests** → final **17 tests** (one transition case added).

It drives a real, mounted GModal (`confirm`, `:show`, `:close-on-ok="false"`, `@cancel` and `@update:show` both calling `setShowConfirm`), and it was affected by the double `cancel`. A probe recorded GModal's `cancel` emissions as `[[],[]]` after `vm.$emit("cancel")` and `[[]]` after clicking Cancel. The synthetic emit closed nothing: the parent then set `show` false, GModal closed the still-open dialog, and `close` emitted `cancel` again, so `setShowConfirm(false)` ran twice. That's idempotent, so no assertion caught it, but the path doesn't happen in production. Both cancel cases now click Cancel, and every send clicks "Send Request", through the shared `clickModalButton`. The test doesn't assert on GModal's own emissions, which would test GModal rather than this component.

Setup bug found: the testing Pinia seeded `initialState: { user: { currentUser } }`, but the store id is `userStore`. The seed was dead, so every case ran with a `null` user, which counts as "not anonymous". The anonymous case passed only because it `$patch`ed the store after mount (with an `as any` cast). The mount now seeds `userStore`, so the authenticated cases really have a registered user. The anonymous case mounts with a typed `AnonymousUser`. With the old `user` key it fails (`expected true to be false`), so the seed is load-bearing. The original case's null → anonymous update, which `showButton` (computed over `userStore.isAnonymous`) reacts to, is kept as its own case. It mounts with `currentUser: null`, asserts the request button renders (a null user isn't anonymous), sets `useUserStore().currentUser` to the anonymous user, flushes, and asserts the root is gone. Without the store update it fails (`expected true to be false`).

What changed: `mountWorkflowMissingToolsRequest({ missingToolIds, currentUser })` awaits the mount, installs Pinia through `withPlugins`, uses `props` and drops the `as object` cast and `setActivePinia`. `getFakeRegisteredUser()` replaces the hand-built `REGISTERED_USER`. `vi.mock("@/api/notifications")` with `vi.mocked(...)` replaces the hoisted mock, which types the payload, and the dead `vi.restoreAllMocks()` is gone. `openRequestModal`, `sendRequest` and `sentRequest()` (asserts exactly one call and returns its payload) name the steps. Selectors are constants, the two config-off cases are an `it.each`, cases are grouped under request button / request modal / sending the request, and auto-unmount is added. `attachTo: document.body` stays, so the dialog is opened in a document as in the inert-page case. Its container is removed on unmount.

Preserved: button text for 2 and 1 tools; hidden when the form flag is off, the notification system is off, there are no tool ids, or the user is anonymous; the payload's tools, workflow id and string remarks (now one exact `toEqual`, so there are no extra keys); remarks give workflow context without the ids; truncation note in the modal; cap at 50 with the remarks note; button disabled in flight; success alert replaces the button; error inside the still-open dialog; error cleared on cancel; singular body without the note; cancel then reopen. Strengthened: the 50-tool cap checks every name (`tool-0`…`tool-49`) instead of the length plus the first and last.

Reuse: `clickModalButton`, `getFakeRegisteredUser`, `getLocalVue`/`withPlugins`, `setMockConfig`. There's no shared anonymous-user factory; similar local literals exist in `useCommandPalette`, `ToolsListCard`, `CuratedWorkflowCard` and `HistoryOptions` tests, a possible follow-up.

Validation, from `client/`: 17 tests pass shuffled (seed `310101`, `NODE_OPTIONS=--no-webstorage`). ESLint (`--max-warnings 0`), Prettier and `vue-tsc --noEmit` pass.

Guidance: `createTestingPinia({ initialState })` is keyed by the store id passed to `defineStore` (`userStore`), not the composable or file name; a wrong key is silently ignored. Follow-up: `Workflow/Run/WorkflowRun.test.js` (line 54) seeds the same dead `user: { currentUser }` key.
