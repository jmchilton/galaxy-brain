## Headline

- **The record agents are told to write can't be read.** The generated `pipeline-*/SKILL.md` says to copy the phase roster from `_assembly.json`, whose rows use `phase:`. The reader only reads `n`. A record written by following the instructions loses every phase status, and the only sign is one warning. This is probably why no real run has ever produced a usable `foundry-run.yml`.
- **Disagreements the spec says to report are chosen silently.**
  - Record vs ledger, for both pipeline and phase status.
  - A misspelled pipeline name falls back to guessing from filenames but is still labelled `recorded`.
  - A duplicate `n`, or an `n` outside the phase list, goes unnoticed.
- **Failures can read as success.**
  - A malformed `foundry-run.yml` shows as "predates the run record".
  - A malformed ledger shows as "not invoked with feedback".
  - If the run is killed mid-trial, `test-pipeline` `run.json` still reads `passed`.
  - The adapter drops a phase's `error`/`failure_kind`.
  - A missing `assembly_sha256` counts as matching the checkout.
