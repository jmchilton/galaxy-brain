## Track B — harness work on top of #569 (red → green)

Base: rebase `pi-harness-resume` onto `run-dashboard-rebase`.

**B1. `test-pipeline` records `foundry_head` (small; #476 identity criterion).**
- `run.json` gains `foundry_head`: `git rev-parse HEAD` of `--root`, or null outside a git repo.
- The adapter maps it to `run.foundry_head` instead of hard-coding null.
- Red tests:
  - `test-pipeline.test.ts`: a mocked run in a temporary git repo has `foundry_head` equal to that repo's HEAD.
  - `run-dashboard-evaluation.test.ts`: record X with checkout HEAD Y → the model shows X. An absent field → null, never Y.
- Could ride inside #569.

**B2. Cast drift warning.**
- The adapter resolves provenance against today's casts. Only the assembly gets `assembly_matches_checkout`.
- Compare each phase's child `run.json.invocation.skill_sha256` with a hash of the current cast, using the runner's existing hash function exported from `gxwf-pi-harness` rather than a second implementation.
- On mismatch, emit a `RunWarning`.
- Red tests: mismatch → warning, match → none, no child record → no claim either way.

**B3. Live Pi evidence (paid, opt-in; also the re-baseline).**
- Run `test-pipeline nextflow-to-galaxy --through 2` locally, then the never-run container pilot. Run `run-dashboard` on each output.
- #569's evidence table has no Pi-run row, so this is real merge evidence.
- It also checks the #643 validator skew on current main.
- Expected cost is about $1–2 per run, based on the #495 numbers.

**B4. Black-box lane cross-check (the biggest item; #476 step 5 + #569's drift problem).**
- The extension appends one line per `foundry_subagent` call to a parent-level `foundry-subagent-calls.jsonl`: seq, skill, child run id, status, artifact ids and hashes. Today child runs land in `FOUNDRY_RUNS_DIR/<skill>-<uuid>` with no parent index.
- A comparator in the dashboard reader checks the agent-written `foundry-run.yml` against that index. Phase order, claimed artifacts and their hashes, and iteration counts must agree. Disagreement becomes a warning; the reader never silently picks one.
- Red tests:
  - Extension test with a mocked runner: N calls → N index lines in call order.
  - Comparator cases: agree; out of order; artifact claimed with no child run; child run missing from the record; iteration count mismatch.
- Then a parent driver: a Pi session loading the `pipeline-*` skill plus the extension, which yields both files. First run is linear only: galaxy-workflow-review, #535.

**B5. Grader shaped to `EvaluationModel` (#476 step 4, first slice).**
- Extend `EvaluationModel` with `properties[]`: `{ id, check, verdict: pass|fail|blocked|unsupported|grader-error, evidence }`.
- `grade` writes `eval.json` beside `run.json`, and the adapter reads it. No new adapter needed.
- Deterministic properties only. Workflow-test assertions use the #662 Galaxy functions.
- First red test: a deterministic property with no oracle → `blocked`, and the health tile is not green.

**B6. Controller loops and branches (#476 step 3).**
- Add `iterations` and `selected` per phase to `run.json`. The adapter maps them where it now writes null.
- The `foundry-run.yml` spec already fixes the semantics: a loop stays one row; a branch records `selected`. Match it.
- Gate on cost caps first (#547).
