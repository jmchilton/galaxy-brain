# Outputs inside the invocation graph

- **Audience:** Galaxy users who run and author workflows, and the Galaxy developers who will review the three pull requests.
- **Length:** 15 main slides, about 14 minutes. Extra slides follow the divider and aren't part of the time budget.
- **Takeaway:** from the invocation graph alone you can now see what a run produced. Hover a step to preview its outputs, turn on Embed Outputs to put every workflow output beside its step without losing the author's layout, and star a step's key output so the step is drawn as that output.
- **The three stages:** each is a branch stacked on the one before. Stage 1 `invocation_graph_output_previews` (hover previews), stage 2 `invocation_graph_embedded_workflow_outputs` (Embed Outputs), stage 3 `invocation_graph_embedded_outputs` (preferred outputs; also the standing branch). All three are polished and wait for John's final review. None has a PR.
- **Demo data:** the E2E test workflow "Output previews" (three inputs, seven tool steps, six labelled workflow outputs) and layout replicas of two IWC workflows, ChIP-seq paired-end (12 steps) and ATAC-seq (42 steps). The replicas have IWC's real positions, labels, edges and workflow outputs, with test tools in place of the real ones, so their cards show placeholder text ("test") and small test tables. Every table in the test workflow is the same small table.
- **Flips:** slide pairs 2→3, 5→6, 8→9 and 12→13, and extras E1→E2→E3 and E4→E5, use frames with the same zoom and pan, so the image swaps in place. Slide 14 puts a stage 2 and a stage 3 frame of the same view side by side.
- **Images:** links are relative to this file. Every invocation frame is 1280×1000 with the same panels, and the deck uses one crop of each, from the invocation header to the bottom of the graph canvas (859×858). The crops drop the activity bar, the masthead (random test user names, storage meter) and the history panel (test-tool dataset names). Crops are in `../screenshots/presentation/slides/`, made by [make_slide_crops.py](make_slide_crops.py); every slide also links its uncropped original. All screenshots are gitignored, so they render in Obsidian on this machine but not on GitHub. No new frames were captured.
- **Published deck:** [Outputs inside the invocation graph](https://claude.ai/artifact/MkMtfLBNXquaSYhGfXyxMz) (private Slides artifact, images uploaded, so it works off this machine). Generated by [build_slides_deck.py](build_slides_deck.py); speaker notes there omit the `[Sources]` lines kept here.

## 11. Star the output that matters

*Stage 3 · Preferred outputs.* In the workflow editor, each tool output gets a star. One per step: the output the step is for.

![The workflow editor for "Output previews (preferred a)" at 100%. Each tool output row has a checkbox, a star and an eye icon. head_table's top_rows and cat_table's out_file1 have filled stars; every other output, such as copy_image's plot, head_cat's summary and numbers' two outputs, has an outline star. Output types read "(input)" because the test tools declare that format. The final step is cut off at the right edge.](../screenshots/presentation/slides/s3_02_editor.png)

![The tooltip over copy_image's star: "Display this step as this output in invocation graphs with embedded outputs."](../screenshots/presentation/slides/s3_03_tooltip.png)

[Open full size](../screenshots/presentation/slides/s3_02_editor.png) · [tooltip](../screenshots/presentation/slides/s3_03_tooltip.png) · uncropped: [02](../screenshots/02_editor_star_output_previews_a.png), [03](../screenshots/03_editor_star_tooltip_hovered.png)

**Focus:** the two filled stars, on head_table's top_rows and on cat_table's out_file1. out_file1 isn't a workflow output: its checkbox is clear.

> Notes: Stage 3 adds the one new piece of workflow metadata in this work. A step whose whole point is one table or plot, such as a MultiQC report, a MACS2 summary or mapping statistics, can name that output as its preferred output. The author stars it in the editor. It's undoable and saved with the workflow, and it needn't be a workflow output. It's stored in an existing JSON column on the step, so there's no database migration, and a .ga export writes it only when it's set.
>
> [Sources] Stage 3 `pr_description.md` ("How it behaves": Editor; "The field: storage, serialization and versions"). Shots: `screenshot_debrief.md` (02, 03; 03 hovered on purpose). Crop: the editor canvas without the Attributes panel; inset from 03.

## 15. Where it stands

| Stage | What it adds | State |
| --- | --- | --- |
| 1 · Hover previews | A popover on each step's outputs. Client-only. | Polished, no PR |
| 2 · Embed Outputs | Workflow outputs as cards, nudge-only layout. Client-only. | Polished, no PR |
| 3 · Preferred outputs | A star in the editor, a new step field, steps drawn as their output. | Polished, no PR |

**Known limits:**

- Steps are drawn as their output only with Embed Outputs on, and a grown step loses its job-count line.
- gxformat2 doesn't know `preferred_output` yet: Format 2 drops it, so IWC workflows shouldn't star outputs until it does.
- Edges keep their routes and pass under cards, and cards aren't drawn in the minimap.
- Large graphs already fit at the 25% minimum zoom, so their cards are thumbnails until you zoom in.

**Ask:** try it on a workflow you know well. Does the embedded layout still look like yours?

> Notes: All three stages are built, hardened and polished on stacked branches, and are waiting for a final read-through. None has been opened as a pull request, so nothing is merged or released. Stages 1 and 2 are client-only. Stage 3 adds a field that becomes part of the workflow file format, so it's the one decision that is hard to undo, and it needs a matching change in gxformat2. The demos use a test workflow and layout replicas with placeholder content; I'd like to hear how it looks on real workflows and real data.
>
> [Sources] Status: `../../invocation_graph_output_previews/index.md` (polished at `90cdc7089d9`; fork CI unrelated reds only, 2026-11-03), `../../invocation_graph_embedded_workflow_outputs/index.md` (polished at `3b546b24e6f`; fork CI running when recorded), `../index.md` (polished at `bfd85ad414f`; fork CI pending). ## E10. How the nudge works

- Steps shrink to 9rem, and cards are a fixed 260×170 (collections 260×120), so the layout runs before any data loads.
- Steps never change rows, so each rule is a lower bound on a step's x against a step placed before it, and one sorted left-to-right pass satisfies them all.
- It runs at most once per animation frame: turning on Embed Outputs on ATAC-seq went from 43 layout runs to 2. Polling a running invocation causes none.
- A grown step tells the layout what size it grew from, so the gap the author left is kept; a step that grows into another row keeps the full gap.
- A 20,000-layout fuzz found no overlaps and no leftward or vertical moves.

> Notes: This is why the layout can't run away the way the spike's did, and why toggling off restores the author's layout exactly: positions are computed, never stored.
>
> [Sources] Stage 2 `implementation_debrief.md` (decision 5; performance: 43 runs to 2; fuzz); `pr_description.md` ("Risk Review Advice"). Stage 3 `pr_description.md` ("How it behaves": Layout; `grewFrom`); `implementation_debrief.md` (decision 10).

## E11. The `preferred_output` field

- Stored in the step's existing `config` JSON column: no migration, and no extra SQL to read it.
- The editor dict always carries it; a `.ga` export writes it only when set, so existing exports are byte-for-byte unchanged.
- Tool steps only. Import and update reject a non-string or a name on a non-tool step. A stale name, after a tool upgrade, just draws the step as usual.
- Each workflow version keeps its own value; the graph uses the invoked version.
- gxformat2 has no such field yet, so Format 2 drops it and its strict schema rejects a `.ga` that has it. That's a gxformat2 follow-up.

> Notes: This is the one change that's hard to undo: once workflows are saved with the key, Galaxy has to keep reading it, and gxformat2 has to match its name and meaning.
>
> [Sources] Stage 3 `pr_description.md` ("The field: storage, serialization and versions"; Risks); `index.md` (Decisions: gxformat2 is a follow-up); performance: 0 SQL statements (`pr_description.md`, performance check).
