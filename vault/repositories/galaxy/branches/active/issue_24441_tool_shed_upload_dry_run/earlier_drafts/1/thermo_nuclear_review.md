The branch's main move, splitting the tip metadata decision out of `set_repository_metadata`, is the right code-judo move: the dry run reuses the decision and never forks the write path. The remaining problems are boundary and abstraction issues around that split.

1. **`TipMetadataPlan.creates_new_revision` is the wrong shape (boundary/type).**
   - The plan exposed a bool plus a nullable row. So `set_repository_metadata` had to write `if plan.creates_new_revision or repository_metadata is None:`, a redundant guard that only exists to narrow the type for mypy.
   - The dry run re-derived "which row is overwritten" from three values: `overwrites = bool(metadata_dict) and not plan.creates_new_revision`, then `... if overwrites and latest else None`.
   - What callers actually need is the row to overwrite, or `None` for a new row. Expose that as `overwritten_repository_metadata`. Then `set_repository_metadata` branches once on it, and the dry run's juggling collapses.
   - `latest_repository_metadata` stays for the tool diff. The new-repo alert stays gated on `new_metadata_required`, which is the base behavior.
   - **Done** (commit 3 + feature usage). The `plan_tip_metadata` docstring also claimed "without changing anything", which contradicts the documented `numeric_revision` backfill. It now says "without storing it".

2. **Bespoke subprocess readers in `hg_util` (canonical-helper duplication).**
   - `get_tip`, `get_changed_paths` and `_hg_output` shelled out to `hg log`/`hg status`.
   - The shed already reads repository state through the mercurial API: `Repository.tip()`, `changeset2rev`, and changelog/ctx helpers. `_hg_output` was a new copy of an error wrapper the file already has three times.
   - The subprocess tip also forced the dry run into `len(repository.hg_repo) + 1  # The repository plus the dry run's commit`, a magic offset.
   - **Done.**
     - `hg_util.get_repo(path)` opens the clone fresh, so the model's `WEAK_HG_REPO_CACHE` doesn't apply.
     - The tip is computed the way `Repository.tip()` computes it.
     - `get_changed_paths(repo, from, to)` uses `repo.status(ctx, ctx)` through `changeset2rev` (null rev `000000000000` checked), and returns sorted, decoded `added`/`removed`/`modified`, which feed `RepositoryUpdateDryRunFiles(**...)` directly.
     - `len(clone_repo)` replaces the `+ 1`. `_hg_output` and `get_tip` are deleted.
