## What was built

- `29a73ee27ef` **Baseline tests.** The spec package `lib/galaxy/tool_util/security/spec/` holds 18 tool XML files, `cases.yml`, pydantic models and a static runner (`review_problems`), shipped through `packages/tool_util/MANIFEST.in`. The job runner is `lib/galaxy/app_unittest_utils/security_review_spec.py`:
  - It builds a real `Tool`, persists users, histories, HDAs and HDCAs in MockApp's sqlite, and runs the real `ToolEvaluator` / `PartialToolEvaluator` `set_compute_environment` + `build()`.
  - `harm: true` builds the command with the review off and runs it in bash, in a temp dir with a 30s timeout.
  - `fault` patches the review, the check or the strict check to raise, for the codes only a bug can reach.
  - Tests: `test/unit/tool_util/security/test_spec.py` and `test/unit/app/tools/test_security_review_spec.py`. These cover both evaluators, log mode, and harm for every red, plus exit 0 for greens.
- `e3be4c68953` **Codes.** `RefusalCode` with 11 codes:
  - 4 violation rules
  - 2 not-plain codes (unchecked place, check error)
  - 5 uncheckable codes (review failed, rewrites, template code, letters are code, strict check error)

  They are threaded through `ToolInputRejected.codes` and the log lines. A completeness test requires every code to have a red, a green and a description.
- `a1dee5e6413` **Docs.** New page `doc/source/admin/tool_security_review.md`. Its codes section is generated by `spec/docs.py`, and a test keeps it fresh. Fences are untagged because prettier rewrites embedded YAML.
- `40a8960e80c` **Review fixes.** Codes now lead the message, because of the 255-character limit on job info. Code mapping fails closed. One user per runner. `serious_findings` moved to `report.py`. Two-code case added. Closer greens.

## Findings along the way (for mvdbeek / Marius)

- The harm check turned up four places where the review counts a value as unsanitized that Galaxy sanitizes at run time. The job check reads the sanitized values, so these jobs run and are harmless. They're pinned as green-only cases, and their review findings are over-approximations:
  - wrapped dataset names and metadata under `sanitize="false"`
  - the element identifier of a plain dataset input
  - user preferences when the sanitizer is on
- `$input.unsanitized` refuses as `uncheckable-template-code`. The runtime-built conditional is the only route to an "uncheckable finding" that isn't refused outright, and it can't be materialized without the upload registry. The two strict reasons in `check_job` share one message anyway, so they're one code (`not-plain-unchecked-place`).
- `galaxy.tool_util.security` imports Cheetah, but `galaxy-tool-util` doesn't require CT3. Planemo and the Tool Shed would need `galaxy-util[template]` or an extra.
