# galaxy#22437 — Feature request: Add server-side enforcement of enable_account_interface

Branch `issue_22437_account_interface_enforcement` — `enable_account_interface` gated the UI and the read side of the account API only, so any authenticated user could change their email, username or password, or delete their account through the API and desynchronize from an SSO/OIDC/LDAP directory; state: implemented per [John's draft plan](https://gist.github.com/jmchilton/ca41e57ec1b1d9352a0fed6601e85eaa) as one commit `358ea3d2472` on dev `7524f5e2507`, pushed to `jmchilton`. Two plan assumptions were corrected against the code: the exception is a 403 not a 400, and the password route is `/password/inputs`; token resets go through `controllers/user.py` so account recovery is unaffected, answering one of the gist's open questions. Per John's call, `PUT /api/users/{user_id}` is guarded per-field so `preferred_object_store_id` stays writable. All four rejections verified red first as genuine 200s, with `err_code` pinned to 403004 because `AuthenticationRequired` is also a 403; 9 + 25 + 13 tests green, lint clean.
