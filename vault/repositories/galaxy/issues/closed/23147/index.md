# galaxy#23147 — SubstitutionError: Substitution error, unfinished block starting at position 90: '$(phykit parsimony_informative_sites \"$f\")"

[Issue](https://github.com/galaxyproject/galaxy/issues/23147)

Branch `issue_23147_expression_template_errors` — Sentry-reported `SubstitutionError` from `cwl_utils`' expression scanner. A user-defined tool's `shell_command` is interpolated as a CWL parameter-reference template, so `$(` opens an expression; the reported tool was a bash script whose command substitution left a quote unbalanced inside `$( )`. Root cause of the *report* (not just the failure): `cwl_utils.expression.do_eval` calls `_logger.exception(e)` before re-raising as `WorkflowException`, so the scanner error reaches the error reporter as an internal traceback with no Galaxy frame — which is exactly the shape of the issue body — and Galaxy's job-prep `except Exception: log.exception` then logged it a second time. Target is `release_26.1` (26.1.2.dev0) as the current bug-fix branch; forward-merges carry it to `dev` (26.2.dev0). Rebasing conflicted once in `managers/tools.py`: 26.1 calls `lint_user_tool_source()` in `create_unprivileged_tool`; kept both, lint first then the template check, matching 26.1's non-walrus style. Verified `lint_user_tool_source` returns no bullets for the unparseable tool, so the lint pipeline does not already cover this and the API test's expected message still fires. `validate_expression_template()` walks `cwl_utils`' own `scanner` (no reimplemented grammar) before anything evaluates and raises `ExpressionTemplateError` naming line, column, the offending text and the `\$(` escape; called from `do_eval` (so cwl_utils never sees or logs an unreadable template), from `create_unprivileged_tool` for `shell_command` plus every configfile (400 instead of storing a tool that can never run), and classified alongside `ParameterValueError` in `BaseJobRunner.prepare_job` so the job fails with the message and no traceback. The recommended `\$(` escape was verified end-to-end rather than assumed. 4 unit + 1 API test, both verified red on the branch point (the old path logged the full `SubstitutionError` at ERROR and raised `WorkflowException`; the API test failed with `KeyError: 'err_code'` because the tool was stored). 592 unit tests pass; 7 failures in `test_metadata.py` / `test_runner_local.py` reproduce on the unmodified base.
