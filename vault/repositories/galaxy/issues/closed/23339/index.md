# galaxy#23339 — `galaxy-test-driver` is published to PyPI but cannot run without a source checkout

[Issue](https://github.com/galaxyproject/galaxy/issues/23339)

Branch `issue_23339_packaged_test_driver` (stacked on `issue_22852_sdist_tests`) — `galaxy-test-driver` is published and current on PyPI but cannot boot an embedded Galaxy from wheels — `driver_util.py` resolves its paths against `galaxy_directory()`, which silently returns `cwd.parent.parent` under any site-packages install, and the wheel ships none of the checkout content those paths point at; the config layer already handles wheel installs via `resource_path` and the driver opts out of it; next: decide whether the driver should route through the existing config resolution or the package should stop advertising standalone use. State: four commits on top of `issue_22852_sdist_tests`, pushed to `jmchilton`, **no PR**. (1) `galaxy_directory()` no longer guesses: it checks the `run.sh` / `lib/galaxy` / `scripts/common_startup.sh` markers `properties._running_from_source()` already used, accepts the cwd itself as well as `cwd.parent.parent` (so an installed Galaxy run from a checkout works), and otherwise raises `GalaxyRootNotFound` naming `GALAXY_INCLUDES_ROOT`; `galaxy_mock` stopped resolving the root at import. Verified against a real `galaxy-util` wheel — what was `<cwd.parent.parent>` is now a named error, and `GALAXY_INCLUDES_ROOT` still overrides. (2) The `FRAMEWORK_*` confs resolve inside galaxy-tool-util via #22852's corpus; each already sets `tool_path="${tool_conf_dir}"`, so the tools resolve beside whichever copy is loaded. (3) driver_util resolves the root where it is used rather than at import, and off a checkout leaves `tool_path` and the static directories unset so `GalaxyAppConfiguration` resolves the bundled tools from galaxy-app and `build_url_map` the static assets from galaxy-web-apps — both branches existed and the driver was overriding them. `import galaxy_test.driver.driver_util` now succeeds from an install outside any checkout. (4) `stock_tool_sources_by_id()` — tool shed runtime — had two checkout roots; `<root>/tools` was the same directory `files(galaxy.tools)` already walks through `bundled`, so every bundled tool was listed twice (865 paths, 685 unique). Same 685 tools, 695 paths, and the tool shed no longer needs `GALAXY_INCLUDES_ROOT` for them. Framework tests 9 passed unchanged before and after; `test/unit/util` 403 passed; `test/unit/tool_shed` + `test/unit/app/tools` identical to the base (25 failed / 16 errors, all missing `hg` or pre-existing `test_metadata` env failures) plus the one new test. **Remaining `galaxy_directory()` consumers in shipped code, not yet converted:** `celery/tasks.py` (datatypes root for the metadata task), `datatypes/registry.py` (`example_datatype_registry_for_sample`, whose sample ships in galaxy-config, which galaxy-data does not depend on), `managers/dbkeys.py`, `jobs/splitters/multi.py` (`extract_dataset_parts.sh` ships nowhere), `jobs/runners/pulsar.py`, `tool_util/unittest_utils/parameters.py` and the checkout-only doc validators in `dataset_collections/types/semantics.py`.

Closed 2026-09-29.
