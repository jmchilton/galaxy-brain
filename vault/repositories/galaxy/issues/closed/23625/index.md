# galaxy#23625 — tool XSD forces an ordering on <requirements> children that the runtime does not

[Issue](https://github.com/galaxyproject/galaxy/issues/23625)

Branch `issue_23625_requirements_xsd_order` — The tool XSD declares `Requirements` as an `xs:sequence`, so `requirement`/`container`/`resource`/`credentials` had to appear in that order and `planemo lint` rejected a tool leading with `<container>` — the error "Element 'requirement': This element is not expected" reads as "you can't have both", which is how it was reported in [planemo#1168](https://github.com/galaxyproject/planemo/issues/1168); the runtime never cared, since `parse_requirements_from_xml` reads each child with its own `findall`. State: one commit `c607642087e` on `release_26.0` `8c61cc36a03`, pushed to `jmchilton`, **no PR**. The sequence is now a repeated `xs:choice` (`xs:all` is impossible — XSD 1.0 forbids `maxOccurs="unbounded"` inside it), matching the `TestAssertions` idiom already in the schema; the two `credentials` `xs:unique` constraints move across unchanged and were re-verified to still reject duplicate names. One linter unit test verified red against the old schema with the exact planemo error then green, plus a doctest pinning the runtime parity claim; all 285 `test/functional/tools` XMLs still validate and `xmllint --format` shows no drift. PR description ready in `vault/agents/gx_branches/old/issue_23625_requirements_xsd_order_pr_description.md` and on the clipboard. Side findings (not fixed): `.ci/validate_test_tools.sh` lints `lib/galaxy/tools/xsd/galaxy.xsd`, a path that has not existed since `tool_util` was split out, and without `set -e` the failing `xmllint` is swallowed — and no GitHub workflow references that script at all, so its test-tool XSD validation runs nowhere; `Credentials` is itself an `xs:sequence` of `variable` then `secret` with the same per-tag parsing, so it carries the same over-strictness.

Closed 2026-09-24.
