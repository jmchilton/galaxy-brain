# galaxy#23521 — Workflow fails (with conditionally executed steps): `Expected [] to be hashable`

[Issue](https://github.com/galaxyproject/galaxy/issues/23521)

Branch `issue_23521_conditional_case_resolution` (also `issue_23521_empty_collection_single_data_param`) — A workflow conditionally executing one of three subworkflows fails with `Expected [] to be hashable` on both 26.0 and 26.1; the original collection-reduction root cause was **disproved** — `_find_collections_to_match` adds a non-multiple data param's collection unconditionally (`modules.py:735-736`, same on 26.0/26.1/dev), so it cannot arrive unmapped. Replacement theory in [[23521_current_case_theory]]: `get_current_case()` returns -1 for a test value matching no `<when>`, `visit_input_values` stores it, and five consumers indexed `cases[-1]` — silently selecting the last case and handing a `multiple="true"` list to a single-dataset param. Verified in isolation, and it explains #19538/#22401's nested-conditional tracebacks and the 0/1/2 element counts. State: branch `issue_23521_conditional_case_resolution` off `release_26.0`, three commits `fa8bc99df19` / `50ba9020634` / `b368b97aa3e`, pushed to `jmchilton`, **no PR**. One accessor `Conditional.get_current_case_inputs(values, strict=True)` replaces all six raw `cases[...]` indexings, split by consequence: execution paths (`wrapped.py`, `evaluation.py`, `wrapped_json.py`) raise a named `RequestParameterInvalidException`, while form building and state scrubbing (`params_to_incoming`, `workflow/extract.py`) pass `strict=False` and get `{}` plus a warning — hard-failing there would lock the editor form needed to fix the bad case.
