# galaxy#23888 — YAML tools have two dialects: the authoring models accept definitions the tool loader misreads

[Issue](https://github.com/galaxyproject/galaxy/issues/23888) · [converge_yaml_disk_and_database_representation](converge_yaml_disk_and_database_representation.md) · [proposed_converge_yaml_disk_and_database_representation](proposed_converge_yaml_disk_and_database_representation.md) · [debrief_converge_yaml_disk_and_database_representation](debrief_converge_yaml_disk_and_database_representation.md) · [reject_unknown_yaml_dataset_output_fields](reject_unknown_yaml_dataset_output_fields.md) · [yaml_grouping_model_loader_mismatch](yaml_grouping_model_loader_mismatch.md)

YAML tool authoring models (API-created tools) and the `YamlToolSource` loader speak different dialects: boolean `value: true` is ignored (no API-created tool can default a boolean to true), repeat/section with `parameters:` crash, scalar outputs are accepted but unloadable, user-tool dumps flip text/multi-select optionality, admin dataset outputs drop unknown keys; target `release_26.1`; umbrella that absorbs the grouping and dataset-output-strictness drafts; filed from the [#23877](https://github.com/galaxyproject/galaxy/pull/23877) docs work; next: cross-boundary regression matrix (red), then fix the boolean default first as the most user-visible bug.
