**P2 — Forward `discarded_data` to the background import** (`lib/galaxy/webapps/galaxy/services/history_contents.py:619–625`)

Could we carry `payload.discarded_data` through `ImportModelStoreTaskRequest` and convert it to `ImportDiscardedDataType` when the worker constructs `ImportOptions`? The new endpoint accepts the same payload as synchronous import, whose documented default is `allow`, but the worker always uses `FORBID`. An independent real-API comparison confirmed that an archive without bytes produces a non-deleted discarded HDA synchronously with omitted/default or explicit `allow`, but a deleted HDA asynchronously. With bytes and `force`, synchronous import discards the HDA while asynchronous import keeps its bytes as `ok`. The same eight policy/archive combinations all agree after a temporary forwarding/conversion fix. An async integration test for the default and explicit policies would cover this; the new UI's explicit `forbid` already matches the current behavior.
