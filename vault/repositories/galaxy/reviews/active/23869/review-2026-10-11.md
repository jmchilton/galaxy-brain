# Review — Galaxy #23869

Reviewed 2026-10-11 at `a3b2e328f0c2e58b9c32323d4635a1fd20a1fb43`, base `dev`; exact pre-PR implementation/configuration was `HEAD^`. Recommendation: **request changes**. Review and draft remain unposted.

The one-file change adds 35 preference tags across 34 datatypes, referencing 21 plugin IDs. Those IDs all exist in the pinned client manifest and exact published npm packages, and their own XML datasource declarations include the directly configured formats. This establishes availability, but the tags also select the automatic dataset Preview, so inheritance and compressed siblings matter.

## Findings

### P2 — Keep specialized defaults from leaking to unrelated datatypes

Location: `lib/galaxy/config/sample/datatypes_conf.xml.sample:944–945` (the new `rrd`/`rerunio` preference); the new `gwas_bgzip`/`locuszoom` mapping at lines 700–701 has the same problem.

The preference resolver compares qualified class-name strings. With `subclass="true"`, Registry creates distinct classes that retain the generic parent's module/name, so `rrd` appears as `galaxy.datatypes.binary.Binary` and `gwas_bgzip` as `galaxy.datatypes.binary.CompressedArchive` in the inheritance map. Adding these defaults therefore makes unrelated datasets inherit them. Running the actual datatype API `show` handler with all exact pinned visualization packages loaded gives `tar → locuszoom` and `hep.root`/`bai → rerunio`, versus no preferred visualization on the exact parent. DatasetView uses that result before its ordinary display/download fallback, despite those plugins rejecting these datasets in their own datasource tests.

Across the full registry, the change affects 104 effective defaults; 58 newly selected defaults fail the selected plugin's datasource applicability tests. Some pre-existing Json alias leakage already exists and is not claimed as newly introduced behavior; these Binary/CompressedArchive examples had no default before this PR. Preserve actual datatype identity when resolving inheritance or otherwise constrain defaults to genuinely compatible formats, with a regression that checks both the intended specialized datatype and an unrelated sibling through the datatype-details path.

### P2 — Do not default compressed FASTA to the text-only alignment viewer

Location: `lib/galaxy/config/sample/datatypes_conf.xml.sample:202`.

`fasta` declares auto-compressed `.gz` and `.bz2` variants, and both inherit the new `alignment` preference. The exact pinned `@galaxyproject/alignment@0.0.9` bundle requests `/api/datasets/{id}/display` and parses the response as FASTA text. The actual datatype `display_data` implementation returns the compressed bytes without a Content-Encoding header. In Chromium, the real bundle renders the plain aligned FASTA control, but gzip and bzip2 versions of that same content both leave an empty viewer and display `Error loading dataset: Cannot read properties of undefined (reading 'seq')`. The actual datatype API returns `alignment` for both compressed types on this branch and no preference on the exact parent.

Restrict this default to uncompressed FASTA until the viewer can decompress or request an appropriate decoded representation. A regression should cover the plain FASTA control plus both automatically generated compressed formats through datatype preference selection and viewer loading.

## Risks

This is a reversible configuration change, but its automatic Preview defaults affect substantially more formats than the edited declarations; fix the two proven compatibility regressions before approval.
