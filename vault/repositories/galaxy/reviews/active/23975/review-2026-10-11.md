## Risks

The implementation is easy to remove, but publishing the `nomad` source type, template v0 and ID-based import URIs creates an API/configuration contract that existing user instances and deferred datasets may retain.

<details><summary>Risk Details</summary>

- Ordinary imports persist downloaded data; reverting the plugin does not remove it, but retained NOMAD URLs need the plugin for later materialization or re-import.
- The source is public-only and read-only. Private uploads and account tokens are deliberately outside this PR.
- Root searches enumerate the complete public catalogue before Galaxy pagination. Slow root/large-upload listing and the cache retention policy can consume worker time and memory; no production-scale load benchmark was run.
- The author explicitly discloses that a folder answering 403 during recursive traversal appears empty. Direct folder listing errors remain visible. This inherited walk behavior can make a recursive scientific-data import incomplete; users should not infer completeness merely from a successful import. It is a known acceptance tradeoff, not an undisclosed regression.
- The new alpha adapter remains responsible for NOMAD API behavior. The conditional lower bound accepts future adapter versions; local verification used exactly 0.1.1.
- Live integration tests depend on public NOMAD service availability and stable public fixture data. No private Oasis, authentication, remote Pulsar staging, or large-scale cache eviction was tested.

</details>

These can be improved in follow-ups; optional tokens and server-side pagination should not be confused with current normal-path correctness blockers. Before merging, assess the remaining purged-input API failure through the usual CI process rather than assuming this feature has an all-green run.
