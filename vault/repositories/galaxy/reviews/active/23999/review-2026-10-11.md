## P2 — Keep CI filters on the tracked source paths

Primary location: `.github/workflows/bioblend.yaml:6–8`. The same change occurs in `config_drift.yaml`, `check_test_class_names.yaml`, `lint.yaml`, `test_galaxy_release.yaml`, `tool_form_harness.yaml`, and `toolshed_frontend.yaml`; `metadata_image.yaml` removes the real source filter altogether.

This PR deliberately retains Python sources in `lib/`, but the positive workflow filters have already been switched to `packages/*/src/...`. Those package paths are Git symlinks (mode `120000`), not the paths of the edited files in a commit. For example, editing the schema through `packages/schema/src/galaxy/schema/history.py` still produces a Git change to `lib/galaxy/schema/history.py`; neither it nor a source-only API edit matches the new BioBlend filters. Consequently those PRs no longer run the BioBlend compatibility suite. The same issue suppresses config drift, dependency-only lint/release checks, test-class checks, tool-form harness and Tool Shed frontend checks; removing `lib/galaxy/**` also drops metadata-image validation for source-only changes.

Keep the real `lib/...` positive filters until a later source-move PR, or add the aliases alongside them if needed. Updating paths used to *read* requirements is harmless because the filesystem follows symlinks; updating workflow *trigger* paths is different because GitHub uses changed paths from the diff. [GitHub's workflow documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#git-diff-comparisons) describes this comparison.

Reproduction: `filter-probe.py` reads the exact base and head workflow configurations and evaluates nine existing source-file paths. All nine match the base filters and none match the PR filters. It also verifies the relevant aliases are tracked symlinks. This is a new loss of CI coverage; the current PR is green because it edits the workflow definitions themselves, which remain positive triggers.

## Risks

This is mainly a reversible tooling change (a two-way door), with moderate operational risk from broad dependency and CI changes rather than a data migration or new user artifact contract.

<details><summary>Risk Details</summary>

- A single universal root lock couples package resolution across the workspace; future package manifest edits can change application dependency pins.
- The requirements regeneration includes numerous upgrades, including FastAPI, Pydantic, Pulsar library and developer tools. Existing startup/functional/package CI is reassuring, but reviewers should assess those upgrades as part of this change rather than assume it is only a coordinator rename.
- Root development and scoped package commands share one environment. This is intended; package isolation still depends on `packages/test.sh`, not on workspace tests passing.
- The identified trigger regression would silently weaken future validation after merge even though this PR currently has green checks.
- The published package/source layout, Galaxy persisted datasets, tool/workflow formats and release package names are not deliberately migrated here; reverting the tooling changes does not need to reverse persisted data transformations.

</details>
