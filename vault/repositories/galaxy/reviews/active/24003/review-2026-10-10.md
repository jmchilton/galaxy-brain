## Risks

This establishes first-entry precedence for duplicate reference values and changes command-template field resolution, so it has a compatibility risk for existing tool artifacts despite being straightforward to revert in code.

<details><summary>Risk Details</summary>

- A later reference row with the same value is ignored even if it has a different name or path; config ordering determines the surviving merged reference.
- Dynamic field lookup now picks one row for every source handled by this method, including loc files and datasets. Tools intentionally relying on concatenating multiple matching rows will observe changed command arguments.
- The added local data-manager reload re-reads the updated tables and can add completion latency. Reload failures remain visible in logs and do not suppress notifications to peers.
- Refgenie write protection prevents YAML corruption. These changes do not migrate stored data or introduce a new API.

</details>

For deployments combining local references with IDC, confirm `tool_data_table_config_path` ordering chooses the intended reference files; the included tests verify local-first precedence and reload consistency.
