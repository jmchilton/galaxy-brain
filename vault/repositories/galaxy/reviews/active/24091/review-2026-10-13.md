## Context

Part of [#23812](https://github.com/galaxyproject/galaxy/issues/23812) (drop bootstrap-vue). Issue says new components go into `@galaxyproject/galaxy-ui` so the Tool Shed can use them; `BFormSelect` is 10 files, 7 here, 3 admin/upload ones (`ContainerIndex`, `ResolutionIndex`, `CollectionCreationConfig`) to follow. Sibling #24090 adds GRadio/GRadioGroup the same way.

## Reuse / abstraction

- No existing native-select component in the client. `Form/Elements/FormSelect.vue` is the vue-multiselect tool-form select (search, multiple, async), not a substitute. `GSelect` fills a real gap; not duplication.
- Component follows the recently merged `GCheckbox` (#24006) closely: same `compatConfig: { COMPONENT_V_MODEL: false }`, `prefix(size)` size classes, `var(--token, fallback)` styling, grey-500 border with the WCAG 1.4.11 note, `focus-visible` outline, and a near-identical spec shape. `GSelect.types.ts` matches the `GTable.types.ts` pattern. Good consistency.
- The 3 remaining `BFormSelect` sites all pass `{value, text}` objects (including `null` placeholders), so the API covers them; no string-array/optgroup/`value-field` features needed.

## Findings

1. **Wrapper path breaks the mirror convention.** Package file is `packages/ui/src/components/Form/GSelect.vue`, wrapper is `client/src/components/BaseComponents/GSelect.vue`. Existing Form siblings mirror: `Form/GForm|GFormInput|GFormLabel` → `BaseComponents/Form/…`; root components (`GCheckbox`) → `BaseComponents/GCheckbox.vue`. #24090 has the same split (`Form/GRadio.vue` → `BaseComponents/GRadio.vue`). Pick one (move the wrapper to `BaseComponents/Form/GSelect.vue`, or the package file to `components/GSelect.vue`) before the follow-up swaps multiply the import paths. Cheap now.
2. **`state` prop has no consumer.** `state` (`g-valid`/`g-invalid`/`aria-invalid`) isn't used by any of the 7 swapped sites nor the 3 remaining ones; `GFormInput` has no validation state either. It's speculative API on a shared package, with two tests. Suggest dropping until a validated form needs it (or point to the intended consumer).
3. **`change` payload differs from BFormSelect.** `BFormSelect` emitted `change` with the selected value; `GSelect` emits the native `Event` (matching `GCheckbox`). Consistent within galaxy-ui and the PR updates the `bulkUploadOperations` JSDoc accordingly, but a mechanical `@change="fn"` swap in a follow-up would silently pass an Event. No current call site binds `@change`. Worth one line in the component doc comment.
4. **Spec doesn't exercise template `v-model`.** `GSelect.test.ts` drives the component through `h()` with explicit `modelValue`/`onUpdate:modelValue` (same as GCheckbox's spec), so the compiled-template `v-model` path the compat opt-out exists for is only covered indirectly (UserSharing, TrsTool specs). `packages/ui/src/components/vModelContract.test.ts` exists for exactly this; one GSelect case there would pin it. A scratch probe of that case passes.
5. **Duplicate option type.** `Markdown/Sections/Elements/handlesMappingJobs.ts` declares its own `SelectOption { value: string; text: string }`, which `JobSelection.vue` imports; galaxy-ui now exports `SelectOption<T>` with the same name and shape. `SelectOption<string>` from galaxy-ui could replace it. Nit.
6. **JobSelection width (question).** `DatasetCollectionElementPicker` got `class="w-auto"` to replace Bootstrap's `.form-inline .custom-select { width: auto }`; `JobSelection` didn't, and its `BInputGroup size="sm"` wrapper now only holds the GSelect, so the `.input-group > .custom-select` rules no longer apply. Probably fine (GSelect is `width: 100%` of a shrink-to-fit group), screenshot 04 is the evidence. The `BInputGroup` could be dropped.
7. **PR body typo.** "the sibling GRadio/GSelect PR" should read GRadio/GRadioGroup (#24090).

Not raised in the draft: `GSelect` styling (grey-500 border, outline focus, Bootstrap control height) differs from `GFormInput` (grey-400 border, box-shadow focus); GSelect is aligned with GCheckbox and with the Bootstrap inputs it sits next to today, so GFormInput is the outlier — a #23702 styling-direction question, not this PR's. New `aria-label`s duplicate adjacent visible text (fine). TrsTool spec's move from `localVue`/`propsData` to `global`/`props` is the documented helper usage.

- **CustomBuilds**: `dataSources`/`fastaFiles` are `{value, text}` (fasta HDAs get `text` from `label`); `id="type"`, `tour_id="type"` fall through to `<select>`. Added `label-for="fasta-file"` + id is an a11y improvement.
- **UserSharing**: `BFormSelectOption` → plain `<option>` children in the slot; `data-description` lands on `<select>`. New spec asserts default `make_accessible_to_shared` and that the picked value reaches `share`.
- **TrsTool**: object option values (`TrsToolVersion`); initial model is the same object instance; Vue's select v-model uses `looseEqual`. New spec checks newest-first order and `onSelect` emission on change.
- **JobSelection / DatasetCollectionElementPicker**: `@input` (BFormSelect emitted value) → `@update:model-value`; object-map `dceToId` converted to `{value: elementId, text: identifier}` options, same as BFormSelect's map semantics. `value?: String` narrowed to `string`.
- **PersonForm / OrganizationForm**: `{value: null, text: "Add attribute"}` placeholder plus the mixin's `$nextTick` reset to `null`. Untested in repo; scratch probe confirms picking an attribute adds its input and the select returns to the placeholder.
- **Selectors**: `navigation.yml` `permissions_change_required_how` (`[data-description=…]`) and `version_select` (`.workflow-version-select`) both still resolve to the `<select>`. `test_custom_builds.py` uses `select[id="type"]` + `select_by_value` — preserved. No `custom-select` selectors anywhere in client/navigation/selenium. No tour YAML references `tour_id`.

## Risks
Adds a public `@galaxyproject/galaxy-ui` component API (also consumed by the Tool Shed) whose shape the rest of the #23812 select migration will copy.
<details><summary>Risk Details</summary>

- `options` contract is `{text, value, disabled}` only; no `value-field`/`text-field`, string arrays, object maps or optgroups like BFormSelect accepted. Fine for all 10 current sites, but callers adapt to it from here on.
- `change` emits the native `Event`, not the value as `BFormSelect` did; follow-up swaps must not move `@change` handlers over mechanically.
- `state` prop is public API with no consumer; once used it's harder to remove.
- Wrapper path (`BaseComponents/GSelect.vue` vs `BaseComponents/Form/…`) becomes the import path in every migrated file; #24090 sets the same precedent for GRadio.
- Visual: selects get the new token styling and caret; restyle is a two-way UI change.
</details>
<details><summary>Risk Review Advice</summary>

Reviewers should treat GSelect's prop/emit surface as the long-lived part: confirm the `{text, value, disabled}` option shape, the native-Event `change`, and whether `state` belongs in v1. Settle the `BaseComponents/` vs `BaseComponents/Form/` wrapper location jointly with #24090 before more swap PRs land.

The call-site swaps themselves are low risk: values, null placeholders and object values behave as before, Selenium/Playwright selectors still hit the `<select>`, and CI is fully green. A quick look at screenshot 04 (Markdown job select width) covers the one layout question.
</details>
