## Review scope and behavior

Read all five changed files and the surrounding NOMAD and shared fsspec code, sibling S3 paths, resolved configuration handling, and the remote-file dialog's 25-item pagination. Also inspected the actual installed `nomad-fsspec==0.4.4` implementation.

- Enrichment runs after pagination. A 101-upload unpaginated result now performs no upload-name lookups; a 25-upload page still gets names, and the 100-upload threshold remains inclusive. The paths and URIs remain stable upload IDs.
- Token normalization occurs in resolved Pydantic configuration, before checking whether `/uploads` has credentials and before opening the backend. Whitespace-only tokens become `None`; trailing newlines are stripped; embedded newlines still produce the backend's readable validation error.
- Moving filesystem initialization inside the download exception handler preserves existing Galaxy exceptions, including their 403 status, while converting backend initialization failures into `MessageException`.
- Shared fsspec listing retains 404 status and includes a descriptive backend reason when the error lacks a filename. Conventional filename-based missing-path errors keep the concise existing message. This applies consistently to fsspec sibling sources.
- The new dependency version keeps a temporary failed upload-facts request out of the permanent ZIP exclusion set and retries it after 60 seconds. A direct probe of the real package verified this boundary.
- The sample configuration and rejection message now describe the IP-based administrator allowlist accurately.
