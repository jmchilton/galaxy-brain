# Review branch `pr_24190_review_0`

Branch `pr_24190_review_0` sits on top of the reviewed commit `a6d7e445d63`. It fixes the three P2 findings in three commits, and each fix has a test that failed before it. Nest now gets its output type from the input collection type instead of from the first element, so an empty `list:paired` gives `list:list:paired`. The tool accepts bare `paired` again, next to `list:paired`. A `list:paired` input still matches directly, because tool forms and workflows prefer a direct match over mapping. Mapped execution now matches what each job produces. A new `Tool.output_collection_type` hook feeds `tool_output_to_structure()`, which lets Nest give the precomputed implicit collection type as `list:list:list:paired` when mapped over `list:list:paired`. Writing the mapped test exposed an older bug as well. In mapped execution, Nest read `incoming["input"].collection`, and for a `DatasetCollectionElement` that is the parent collection, not the slice. Each job therefore nested the slice's whole parent. Nest now uses `get_collection()`. The workflow-editor half of P2 1 is not fixed. `ToolModule.get_all_outputs()` still advertises the static `list:list`, and the client `OutputCollectionTerminal` can only use a fixed type or pass the `type_source` type through unchanged. Saying "input type plus one list level" would need a new tool-XML attribute and changes to the XSD and schema models, `terminals.ts`, and the client tests. That would be a new tool-spec abstraction on a release branch.

- `71b1112f41a` Keep Nest output paired type for empty list:paired input. Adds `nest_collection_type()` and derives the outer and inner types from `hdca.collection.collection_type` before the loop. Tested by `TestToolsApi::test_nest_empty_list_of_pairs`, which got `list:list` before the fix.
- `a919345e2f8` Keep bare paired input accepted by Nest collection. Changes the input to `list,paired,list:paired` and adds three tests:
  - `TestToolsApi::test_nest_offers_paired_and_list_of_pairs_inputs`: the pair was not offered before the fix.
  - A bare-pair `<test>` in the tool XML, which checks the `list:list` output.
  - A rewritten matching unit test: all three types match directly, and `list:list:paired` maps over `list:paired`.
- `6f36ac97004` Expose Nest output type to mapped output structure. Adds the `Tool.output_collection_type` hook, wires it through `ExecutionTracker._mapped_output_structure` to `tool_output_to_structure(collection_type=...)`, and makes Nest nest the mapped slice through `get_collection()`. Tested by `TestToolsApi::test_nest_map_over_list_of_lists_of_pairs`. Before the fix the outer type was `list:list:list`, and once the type was fixed each element was still a wrongly typed parent copy.
