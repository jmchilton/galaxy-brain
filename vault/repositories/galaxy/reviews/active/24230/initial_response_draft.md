**P2: Search index still has a second writer** — `lib/galaxy/tools/cached_toolbox.py:1730` (`remove_tool_by_id`). Fix #7 makes the config watcher the only index writer by gating call sites, but `remove_tool_by_id` still calls `app.reindex_tool_search()` in whichever process served the uninstall. A non-watcher worker and the watcher (via the broadcast) then both write, and with incremental builds a lagging writer can commit last and delete documents a peer just added. Suggest moving the rule into the app: a `writes_tool_search_index` property (`False` on `GalaxyManagerApplication`, `is_webapp and is_config_watcher` on `UniverseApplication`) checked by `reindex_tool_search` / `ensure_tool_search_index`, dropping `_writes_tool_search_index` from queue_worker. That also gives the watcher-only rule a unit test, which it currently lacks. [Fix](https://github.com/jmchilton/galaxy/commit/dda040ae17ec6891cbe5f1042319c21a71b6ea6e)

**P2: Install pre-index branches on `isinstance(CachedToolBox)` and runs for every `get_repository_tools_tups` caller** — `lib/galaxy/tool_shed/galaxy_install/metadata/installed_repository_metadata_manager.py:91-107`. Update, activate and metadata reset go through this too, so already-indexed tools now cost a populate plus a fleet-wide `reload_tool_source_cache` broadcast. The `isinstance` check also cuts against the no-op `batch_index_writes` hook this PR adds to the base `ToolBox`. Suggest an `index_tool_files` no-op on `AbstractToolBox` beside `materialize_tool`, with the `CachedToolBox` override populating only guids the index doesn't hold (filtering by guid, not path, so a version bump at the same path still re-indexes).
