# Filtered findings — PR #24407

- **SQLite vs Postgres divergence in `populated_optimized`** (part of default P2 1): disproved. On SQLite the outerjoin path joins each child collection's `populated_state` when `collection_attributes` is passed, so an empty FAILED sub-collection is still seen. The surviving map-over behavior change is kept as P2 1.
- **Map-over failure can lag up to 300s when the empty failed element's job finishes last**: pre-existing scheduler latency, not introduced by the PR. A mapped job's sub-collection is a bare `DatasetCollection`, so changing it doesn't bump `history_audit` (the triggers cover only HDA, HDCA and history), and `ready_to_schedule_more` waits for `GALAXY_SCHEDULER_BACKFILL_SECONDS`. Before the PR, an empty-OK sub-collection stalled the same way. Noted in P2 1's details. It is also why the map-over test is at the tools-API level and not a workflow test, which was order-dependent locally (reached `failed` within 60s in 2 of 5 runs).
