Branch `pr_24484_review_0` is based on the reviewed commit `baeca0d7dc6`. It does four things. First, Pulsar jobs without staging work again on the pinned pulsar-galaxy-lib 0.16.0, because `url` is passed to `ClientInput` only when staging issued one. Second, input metadata files stay out of the handler's cache: the wrappers hand the `MetadataFile` itself to the compute environment, which replaces the reverse path lookup. Third, `object_store_staging` is parsed once into a typed mode before tool evaluation, staging URL construction moves next to the signer, and both runner-facing managers share one active-job check. Fourth, the tests are tightened: redirect mode is proven to redirect, the runner unit tests use pure helpers instead of fakes, integration tests share one static-job helper, and unit tests that duplicate integration coverage are dropped. Nothing changes the pulsar-galaxy-lib pin. Tests on the staging path ran against galaxyproject/pulsar#553 by putting it first on `PYTHONPATH`. Tests without staging ran on the pinned 0.16.0.

- `b1ea1389707` Pass url to ClientInput only when staging issues one: adds `_client_input`, so destinations without staging no longer hit `TypeError` on 0.16.0.
- `33f1cd304b9` Don't pull staged input metadata files into the handler cache: adds `ComputeEnvironment.input_metadata_file_path`, which Pulsar overrides with `sync_cache=False` to record the file id, drops `_metadata_file_with_path`, and asserts in the BAM integration test that `bam_index` stays out of the cache.
- `54bdaf9283f` Validate object_store_staging once, before tool evaluation: adds the `ObjectStoreStagingMode` Literal and `_object_store_staging()`, which rejects unknown modes and a missing `rewrite_parameters` before `prepare`.

- `3d9b7bc4603` Assert redirect-mode Pulsar jobs were served by redirect: the redirect class records `staged_input` redirects and asserts them for the dataset and `bam_index`.
