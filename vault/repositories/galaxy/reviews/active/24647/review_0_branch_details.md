Branch `pr_24647_review_0` starts from the reviewed commit `7247fea9983`. It adds integration tests that run real jobs under extended metadata and tamper with the model store each job writes to `metadata/outputs_populated`. The tampered stores name another user's dataset, job or collection, or link a user-defined tool's output to a server file, and every job must end in error with the victim unchanged. With the PR's `editable_objects=` argument removed from `finish`, all four tests fail. The branch also blocks `uuid` changes to existing outputs of user-defined tools, and it loads a metadata file uuid's rows once instead of twice.

- `dda2d1ace28` Test that a job's tampered extended metadata can't edit objects it doesn't own: adds four tampering tests to `TestExtendedMetadataSecurityIntegration` (dataset, job, collection, user-defined tool `external_filename`), using a `mock.patch.object` wrapper around `store.get_import_model_store_for_directory`.
- `8e90673a485` Refuse uuid changes to existing outputs of user-defined tools: makes `assert_dataset_attributes_editable` refuse a new `uuid` for an existing dataset, adds a unit forge case, and adds an untampered user-defined tool run as a positive control to the integration test.
- `4d16bd86879` Query a metadata file uuid's rows once during import: `replace_metadata_file` loads the rows once, ordered by id, and uses them for both the editability check and the row to reuse.
