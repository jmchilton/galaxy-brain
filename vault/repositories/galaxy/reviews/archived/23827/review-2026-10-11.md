## Findings

### P2 — Preserve the discarded-data policy when queuing the import

Location: `lib/galaxy/webapps/galaxy/services/history_contents.py:619–625`.

`CreateHistoryContentFromStore` accepts `discarded_data` (default `allow`), but the new task request drops it. `ImportModelStoreTaskRequest` has no corresponding field, and `ModelStoreManager.import_model_store()` constructs `ImportOptions` without one, whose default is `FORBID`. Thus the new asynchronous endpoint silently changes the documented default and ignores explicit `allow` and `force` requests. The synchronous sibling converts and forwards the selected policy.

A real API comparison imports the same valid HTTP model-store export through both endpoints: for an export without files plus `allow`, the synchronous endpoint keeps a visible, non-deleted `discarded` HDA, while the async endpoint marks it deleted; for a full export plus `force`, the synchronous endpoint creates a non-deleted `discarded` HDA, while the async endpoint imports an `ok` HDA. Both async tasks report success. This is a new endpoint-contract bug; the existing task's fixed policy predates this PR, but exposing it with this payload requires carrying the policy through.

Carry the policy in the task request and convert it to `ImportDiscardedDataType` when constructing `ImportOptions`, as the synchronous helper already does. Cover omitted/default, `allow`, and `force` requests through the actual async endpoint. The current upload UI explicitly sends `forbid`, so its happy path is unaffected.

### P2 — Keep export outcome tracking alive after closing the dialog

Location: `client/src/components/History/Content/ExportToAnotherGalaxyDialog.vue:96–101`.

Changing `item` to `null` when the dialog closes stops the only Celery task monitor. Recent Exports stores only the short-term-storage request ID, and therefore falls back to polling storage readiness. A failed export also finalizes its storage (`storage_context` calls `cancel`, which calls `finalize`), so readiness becomes true on failure too. If a user closes this dialog while a large export is running, a later failure is shown as READY in Recent Exports and offers a broken download/copy link. Switching to a different item has the same problem for the previous export.

An added diagnostic using the real dialog, task monitor, and persistent storage monitor delays a FAILURE response, closes the dialog, then releases the response and polls storage readiness. The failure remains unrecorded and the Recent Exports monitor reports completion with `taskStatus: READY` and `hasFailed: false`. The existing failed-export test covers only keeping the dialog open. Preserve outcome monitoring independently of whichever item is currently shown, or persist the Celery task ID so Recent Exports can verify the actual task outcome. Add a close-before-failure regression test.

## Risks

The new public API and durable imported copies establish compatibility commitments; the temporary export link also creates an intentional period during which the exported content cannot be withdrawn through this dialog.

<details><summary>Risk Details</summary>

- The async endpoint introduces documented import behavior and returns a task result instead of imported content. Preserve sibling payload semantics and make task failures observable.
- Copies import dataset bytes and persisted datatype, genome build, metadata and collection structure. A code rollback does not remove previously imported copies or repair incorrectly deleted/discarded HDAs.
- The source data remains intact; users can delete unwanted target copies and import again. This reduces recovery risk compared with an in-place migration.
- The existing short-term-storage mechanism serves the link without login until expiry, usually one day. The dialog explicitly discloses access and lack of withdrawal. Human review should confirm that wording and the operational lifetime are appropriate for these servers.
- Large exports and imports consume temporary disk, object-store space and background-worker capacity. Deployment-specific quotas, external authenticated sources, two independently configured Galaxies, and real browser interaction were not exercised locally.
- Collection tags are newly serialized and restored through the common model-store code, affecting other history/store import paths as well as this upload method. The model-store suite and round trip passed; no database migration is introduced.

</details>

<details><summary>Risk Review Advice</summary>

Review the payload contract and user-facing export lifetime before publishing the endpoint. Ensure closing a modal does not discard the only reliable failure signal. The existing end-to-end tests are useful foundations: extend them for non-default discarded-data policies and add the dialog-close failure case rather than relying only on stubbed request-body assertions.

</details>
