Reviewed HEAD: `0cbea855736f52a43d9db630a4d4a5ee1b92d030`; base `dev`, diffed against merge-base `91d93c238c0c` with freshly fetched `origin/dev`. 21 files, +1509/-254, 16 commits (bug fixes each as failing-test + fix pair).

Verdict: approve with small follow-ups. No correctness blockers. The watermark fix is right and well tested; the dialog/composable extraction is a genuine reusable abstraction. Findings below are mostly reuse/divergence from sibling paths, one small real display bug, and a UX wording point.

## Findings

### Real (small)

1. **Local-feed descriptions show HTML entities literally.** `CuratedWorkflowCard.vue` `plainDescription` strips tags with a regex but never decodes entities. Local mode sends `sanitize_html(owner_annotation)` (`services/workflows.py` `_local_to_curated`), which escapes `&`/`<` — verified: `sanitize_html('R&D a < b')` → `'R&amp;D a &lt; b'`. The card (and its `title`) will now show `R&amp;D`. Previously GCard rendered the description as markup, so this is a regression for local feeds only. Fix: take `textContent` from a parsed fragment (`DOMParser`) instead of the regex; add a vitest case with `&amp;`.

2. **"Already imported" counts edited copies — diverges from the established convention.** `WorkflowsManager.trs_imports` deliberately scans *every* revision because an editor save drops `source_metadata`. But Galaxy drops it on purpose: `model/__init__.py` (Workflow.copy) says source_metadata "records where this exact content was fetched from and is dropped whenever a workflow is modified (see test_trs_import)". The sibling lookup `get_workflow_by_trs_id_and_version` (`managers/workflows.py` ~2722, used for TRS subworkflow reuse) joins on `latest_workflow_id` only, so the two "find this user's TRS import" queries now disagree on what counts. Consequence: a heavily edited copy is labelled "In your workflows", compared by its original release ("You have v0.1"), and the primary **Run** says "Run your imported copy". Defensible UX, but it should be a conscious decision; ideally one shared query helper with an explicit `include_modified` choice, or at least a cross-reference comment in both places.

3. **TRS id parsing re-implemented.** `curated.entry_trs_tool_id` splits the projected URL on `/tools/` and uses `unquote_plus`. What an import actually records comes from `TrsProxy._match_url` (`TRS_URL_REGEX` + `unquote`, not `unquote_plus`). The projection builds URLs with `quote_plus`, so ids containing a space/`+` would decode differently than the stored `trs_tool_id`. Not hit by current IWC ids, but the function's docstring promises "the TRS tool id an import records" — reuse `TRS_URL_REGEX`/the proxy's parse so that holds by construction, or project `trsID` directly (the projection is versioned, so a bump is the established path).

4. **Three release comparators, two new ones already disagree.** Python `_release_order` (in `managers/workflows.py`) and TS `compareReleases` (in the card) are new; `Workflow/Import/TrsTool.vue` already has `parseSemver`/`compareSemverDesc`. Python treats `v0.1.0` > `v0.1` (tuple length); TS pads zeros and calls them equal. Low impact, but it's drift on day one. Options: have the server emit the comparison (it already knows `release` and `imported_version`) so the client doesn't parse versions, or move one TS helper into `utils/` shared with `TrsTool.vue`. `_release_order` is also TRS/curated-specific and would sit better beside `find_imports` in `workflow/curated.py` than in the manager module.

5. **Request button can ask for an already-installed data manager tool.** For non-admins, `hide_data_manager_tools` reports installed data-manager tools as missing (correct for runnability). The new card request sends `workflow.missing_tools` verbatim, so a non-admin can file an install request for a tool admins already have. Edge case (IWC workflows rarely use DMs); either filter them from the request or tweak the wording.

### Reuse / design

6. **Composable not adopted at the other caller.** `useCanRequestToolInstallation` extracts the notification + request-form + non-anonymous gate, but `components/Panels/ToolBox.vue:50` still inlines the identical check. Cheap to switch it in this PR so there's one gate.
7. **"Update to v0.2" doesn't update.** The import action label says "Update to vX" but creates a second workflow alongside (the tooltip says so). Users will learn this wording; "Import vX" (with "You have v0.1" already in the footer) is more honest.
8. **Second regex filter-toggle.** `toggleRunnable` copies the `toggleCollection` regex-edit pattern (justified in #23669 because `Filtering.setFilterValue` rebuilds the text and drops free text). Two copies now; a tiny shared `toggleTerm(text, term)` helper in `curatedFilters.ts` would keep them aligned. Nit.

### Nits (cheap)

- Every card with missing tools mounts its own `ToolInstallationRequestDialog`/GModal (`v-if="canRequestMissingTools"`); gate it on `showInstallationRequest` instead to avoid ~page-size dialogs.
- `trs_imports(sa_session, user_id)` takes a session argument while the sibling `get_workflow_by_trs_id_and_version` uses `self.app.model.session`; pick one style.
- `trs_imports` ignores `trs_server`; an id collision across TRS servers is implausible for IWC, fine to leave.

Tests cover stale-CDN, undated GET, cold download.

- **Imports API**: anonymous → no lookup; only the requester's non-deleted, non-hidden workflows; encoded ids consistent with existing `stored_workflow_id: str` style. Integration test sets source_metadata directly (avoids Dockstore) and checks anonymous isolation.

## Risks

Additive API fields and a new `is:runnable` search term on `GET /api/workflows/curated` plus new user-facing card states are modest one-way doors; the backend refresh and layout changes are two-way.

<details><summary>Risk Details</summary>

- New optional response fields `imported_workflow_id` / `imported_version` on `CuratedWorkflow`; once clients rely on them, their semantics (which copy wins, whether edited copies count) are hard to change.
- New `is:` filter namespace on the curated search endpoint (`is:runnable`); other `is:` flags currently match nothing, which constrains future flags.
- Recommended default ordering now means "fewest missing tools first" — documented in the OpenAPI description.
- UI vocabulary users learn: "Ready to run here", "In your workflows", "You have vX", "Update to vX" (which actually imports a new copy).
- New `<projection>.last-modified` sidecar file next to the catalog projection; operators may see it on disk.
- Non-admin users can now send tool-installation requests from the curated tab (gated by existing `enable_notification_system` + `enable_tool_installation_request_form`), potentially increasing admin notification volume.
</details>

<details><summary>Risk Review Advice</summary>

Humans should decide whether an edited copy of a TRS import should still count as "the import" — this PR says yes, while Galaxy's `source_metadata` convention and `get_workflow_by_trs_id_and_version` say no. That choice is baked into the new API field's description, so settle it before merge.

Also worth a glance: the "Update to vX" label (it never updates in place), and whether admins on busy instances want curated-tab install requests enabled under the same config switch as the run page.
</details>
