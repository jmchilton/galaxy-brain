## Findings and relationship to #23869

The use of class identity removes the generated-class-name collision without modifying the client-facing `view_mapping()` contract. Direct extension mappings retain priority. Walking the actual MRO chooses the nearest mapped ancestor; the old implementation instead chose the first matching entry in configuration order. Building only the mapped-class lookup also avoids walking every datatype's ancestry on each request. No cache is introduced, so updated mappings remain visible.

Using #23869's unchanged sample config at `a3b2e328f0c2e58b9c32323d4635a1fd20a1fb43` with #24097's registry and resolver confirms that `rrd` still selects rerunio and `gwas_bgzip` still selects locuszoom, while `hep.root`, `bai`, `tabix`, `gz`, `tar`, and `tar.gz` lose the unrelated preferences. This resolves the mechanism behind our first #23869 finding.

It does **not** resolve the second finding: `fasta.gz` and `fasta.bz2` genuinely inherit from FASTA and still select alignment. The previously retained browser evidence in [#23869](../../active/23869/index.md) demonstrates the pinned viewer's inability to decode those bytes. This review rechecked preference selection, not the browser rendering. #23869 still needs to constrain compressed defaults or introduce viewer support; its other default-view choices also remain separate decisions.

[Ayslam's October 13 comment](https://github.com/galaxyproject/galaxy/pull/23869#issuecomment-6147278065) proposes explicit-only preferences, without inheritance. #24097 deliberately retains real inheritance (`mbi` → h5web, `ome.tiff` → tiffviewer, `probam` → igv). The implementation is sound for that policy, but the two policies should not be described as equivalent. This is a maintainer decision, not a newly introduced runtime failure.

Non-blocking test suggestion: add a case with both a broad and a closer mapped ancestor, inserting the broad mapping first. The existing inheritance cases prove fallback works but do not lock in nearest-ancestor precedence. An independent probe using real Binary/H5/mbi classes confirms the new behavior and the old implementation's order dependence.

## Risks

Risks are minimal: this is a reversible preferred-Preview resolver correction, with no stored-data migration or new tool/workflow contract (a two-way door). Custom configs with several mapped ancestors may deliberately change from configuration-order priority to nearest-ancestor priority. Maintainers should explicitly choose whether genuine inheritance is desired; compressed formats can inherit viewers that cannot consume their bytes, which remains a separate mapping/viewer issue.
