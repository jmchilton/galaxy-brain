# Filtered findings: #24299 initial review

- **Initial review P1 1 (the post-run success page collapses the invocation graph).** Disproved. For a single invocation, `WorkflowRun.handleInvocations` does `router.push("/workflows/invocations/<id>?success=true")`, so the post-run view is the routed page, which has a definite height. `WorkflowRunSuccess` only renders for more than one invocation and then shows `GridInvocation`, which doesn't pass `is-full-page`. Live check on PR head `90a64400825`: after running a two-step workflow, the post-run page rendered the graph at 590px with no step selected, and at 329px graph / 323px step card with a step selected (`screenshots/post_run_success_pr_head.png`). A drafted fix (`fillHeight = isFullPage && !success`) would have broken that page, so it was dropped from the review branch.
- **Initial review P3 3, third bullet (re-click could scroll the card body to top in full page).** Not actionable. The reviewer marked it "fine as is, optional".
- **Side note, not raised by a reviewer:** the `v-else-if="props.invocations.length === 1"` branch in `WorkflowRunSuccess.vue` is unreachable: `WorkflowRun.vue` assigns `invocations.value` only in the multi-invocation `else` branch, and `WorkflowRunSuccess` has no other caller. It is pre-existing code this PR doesn't touch, so it was kept out of the posted review.
