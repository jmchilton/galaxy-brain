Review branch `pr_1744_review_0`, cut from the reviewed commit `d3b58601`, stops `stage_in` from normalizing a workflow unless the job holds a list that could be a multiple-value parameter value. Before this, native workflows with `color` or `directory_uri` inputs crashed at staging. A native `color` fixture covers it, with a scalar job and with a list-of-Files collection job. The branch also rewrites the remote-workflow test to fake Galaxy's workflow download instead of patching an internal helper, so it is red on master for the real reason. It adds the `gxid://workflow-instance/` case, trims `DATA_INPUT_TYPES` to the types `inputs_normalized` emits, adds a native `.ga` `parameter_input_labels` test, and adds a Galaxy-backed `planemo run` test (written, not run locally) skipped on releases before 24.2.

- `f93fe7dc` Only read workflow parameter inputs when a job has parameter lists — gates the lookup behind `_has_parameter_list(job)`, with `tests/data/wf_color_param_input.ga` and a parametrized regression test that fails on the PR head and passes on master.
- `aab5ec4b` Fake Galaxy workflow download in remote stage_in test — sets `config.user_gi.workflows._get` instead of patching `get_dict_from_workflow`, and drops the call-argument assertion.
- `e98ca8eb` Cover gxid://workflow-instance/ in remote stage_in test — parametrizes over URIs with a `side_effect` that asserts the download path and `instance` param.
- `66818554` Drop DATA_INPUT_TYPES aliases inputs_normalized never emits — reduces the set to `{"data", "collection"}`.
- `0afeb7a4` Test parameter_input_labels on a native workflow — adds `tests/data/wf_native_param_inputs.ga` with text-multiple, integer, data and collection inputs.
- `5a205ab3` Run multiple-value parameter input workflow against Galaxy — adds `test_run_multiple_value_parameter_inputs` and `tests/data/wf_multiple_param_inputs-job.yml`, skipped on Galaxy releases before 24.2.
