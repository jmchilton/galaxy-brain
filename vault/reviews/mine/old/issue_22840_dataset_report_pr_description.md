# Fix 500 on the dataset tool-markdown report endpoint

Fixes #22840.

`GET /api/datasets/{dataset_id}/report` 500s for every `tool_markdown` dataset on `dev`.
`DatasetsService.report()` unpacks two values from `ready_galaxy_markdown_for_export()`,
which has returned a three-tuple since `689aaf013d`:

```python
content, extra_attributes = ready_galaxy_markdown_for_export(trans, internal_markdown)
```

so the request raises `ValueError: too many values to unpack (expected 2)` before a
response is built. The other three callers (`managers/pages.py`, `api/chat.py`, the
workflow report generator) were all updated at the time; this one was missed.

## The fix

Unpack three values and return the embed-expanded markdown, which is what
`managers/pages.py` puts in its display `content`. `ToolReport.vue` renders the response
read-only through `Markdown.vue`, so there is no editor variant to keep.

## Tests

`lib/galaxy_test/api/test_datasets.py::TestDatasetsApi::test_report_for_tool_markdown_dataset`
runs `markdown_report_from_script`, then asserts the report endpoint returns 200 with the
rendered document and the generate attributes. Verified red (500) before the fix and green
after.

The test also pins *which* variant is returned. Every markdown report fixture used only
fenced ` ```galaxy ` blocks, for which the two variants are byte-identical, so the test
would have passed against the wrong one. `markdown_report_simple_script.py` gained a line
using the embedded form:

```
Generated by Galaxy ${galaxy generate_galaxy_version()}.
```

which is expanded in `content_embed_expanded` and left literal in the plain export. The
script tool was used rather than `markdown_report_simple.xml` because `${...}` inside a
`<configfile>` is Cheetah syntax. All three `markdown_report_*` framework tool tests still
pass.
