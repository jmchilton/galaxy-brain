## Original review threads

Both authoritative review threads on #1512 are genuinely addressed.

### Reuse `job_config_init`

Marius asked the guide to use
[`galaxy-job-config-init`](https://github.com/galaxyproject/planemo/pull/1512#discussion_r2157125688),
and John clarified that the established Planemo abstraction is
[`planemo job_config_init`](https://github.com/galaxyproject/planemo/pull/1512#discussion_r2157385247).

The replacement removes both hand-maintained Galaxy job configurations. It now
generates the ordinary Slurm and Slurm-with-TPV variants with:

```console
planemo job_config_init --runner slurm --singularity --galaxy_version 25.0
planemo job_config_init --runner slurm --tpv --singularity --galaxy_version 25.0
```

I ran both documented commands against the current Planemo implementation in
isolated temporary directories. Both wrote and parsed as `job_conf.yml`. The
ordinary configuration selected the Slurm runner and included `tmp_dir: true`;
the TPV configuration selected `dynamic_tpv`, included the shared
`https://gxy.io/tpv/db.yml` database, and generated the `tpvdb_slurm`
destination described by the guide. The subsequent `planemo run` examples use
the generated filename consistently.

The final follow-up also reuses the existing `planemo slurm_init` command instead
of duplicating slurm-drmaa download and build instructions. That command builds
the currently supported release and copies `libdrmaa.so` to the Planemo
workspace, whose default path is correctly documented as
`~/.planemo/libdrmaa.so`.

### Do not prescribe shared `TMPDIR`

Marius noted that a manually shared temporary directory
[`should not be necessary`](https://github.com/galaxyproject/planemo/pull/1512#discussion_r2157125858)
because `tmp_dir: true` is the default.

The replacement removes the `TMPDIR=... planemo run` workaround. It accurately
explains that the generated destinations use `tmp_dir: true`, while retaining
the distinct and necessary requirement that Galaxy working directories and
input data be visible to compute nodes.

## Complete diff review

The final diff adds `docs/_running_slurm.rst` and includes it from
`docs/running.rst`; there are no implementation or test changes.

- The RST heading hierarchy, include, internal command references, named links,
  lists, and console blocks render correctly.
- The command examples agree with current CLI option names and generated output.
- The guide avoids the original conflict between a Singularity job
  configuration and `--biocontainers` examples.
- TPV guidance leaves site-specific Slurm resource translation to
  `native_specification` instead of publishing a misleading universal template.
- Database, failed Tool Shed startup, and port-collision troubleshooting remain
  useful without overclaiming the cause of a later BioBlend connection error.
- No tests or assertions were removed or weakened. Existing
  `job_config_init` tests already cover Slurm, TPV, Singularity, and the Galaxy
  25.0 configuration shape.

The only residual limitation is environmental: this review could not perform a
real Slurm submission on the clusters named by the original author. That is not
a merge blocker for this documentation-only change because the documented
configuration is generated by Planemo itself and site-specific scheduler values
are explicitly left for administrators to supply.
